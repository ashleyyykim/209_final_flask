Intended Audience

Built for NBA fans and casual analysts who follow the league but don't necessarily track box-score stats. Basic knowledge of the playoffs and the stars is assumed. PIE isn't, so every chart explains it before asking you to read it. No stats background required, nothing oversimplified to compensate.

Data Source

Source

All data comes from the official NBA Stats API, pulled with the nba_api Python package

Metric

Every chart on this site is built around Player Impact Estimate (PIE), the NBA's own single-number measure of how much a player contributed to a given game.

How PIE is Calculated
PIE = PTS + FGM + FTM − FGA − FTA + DREB + 0.5×OREB + AST + STL + 0.5×BLK − PF − TOV same sum, across both teams combined, in that game

In plain terms: PIE is what percentage of everything that happened in the game, across both teams, one player was responsible for.

Source: NBA.com Stat Glossary, "PIE"

Why PIE

A single raw stat like points or rebounds only tells one side of the story, a player can score a lot while turning the ball over or getting outplayed on defense. Composite alternatives like PER or Win Shares fix that, but they lean on season-long league averages and involve a proprietary calculation that aren't in the NBA API. PIE folds the full box score, both ends of the floor, into one number that's published directly by the NBA, computed fresh per game, and pulled from the same API this project already uses, so nothing here depends on a formula this project can't verify.

Tools Used

Data Processing

All data comes from the official NBA Stats API, pulled with the nba_api Python package and cleaned with pandas. Play-in games are filtered out before any playoff-level analysis, and player and team records are joined by season and team to build the player, team, and series-level views each hypothesis needs.

Visualization Design and Implementation

Every chart is authored in Altair, which compiles to Vega-Lite, and saved as a standalone JSON spec loaded on the page with vega-embed.

Website and Deployment

The site itself is a Flask app: templates render the page shell and chart containers, and static files hold the CSS, JavaScript, and saved chart specs. The repo lives on GitHub and auto-deploys to Vercel on every push to main, so changes go live without a separate build step.
